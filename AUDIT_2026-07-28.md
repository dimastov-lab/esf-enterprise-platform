## 0. Итоговый вердикт

Это **на удивление зрелый RC-код** для проекта такого объёма (~5 900 строк реального Python в чистой слоёной архитектуре). Ключевые механизмы безопасности — **реальны и подтверждены тестами**: объектная авторизация (owner/admin) без единого IDOR, CSRF с константным сравнением, неизменяемость снапшотов на **двух** уровнях (ORM + DB-триггеры), атомарная публикация с `SELECT … FOR UPDATE` и sha256-верификацией, fail-closed проверка `SECRET_KEY` в проде. **Critical/High уязвимостей в коде не найдено.**

Основные проблемы лежат **не в корректности кода**, а в трёх плоскостях:
1. **Стратегико-юридический риск** — продукт является пиксель-точным клоном официальной госформы КР и по умолчанию ссылается на реальный домен `esf.salyk.kg`, при этом сам же в документации признаёт отсутствие юридической силы. Это самый серьёзный риск всего проекта.
2. **Готовность к продакшену** — самоподписанные `localhost`-сертификаты, реальные секреты в открытом виде на синхронизируемом Desktop, Docker-образ ни разу не собирается в CI.
3. **Гигиена репозитория и документации** — 626 МБ личных юр/фин материалов физически в папке репо, ~1 700 строк маркетинговой «отчётной» документации с выдуманной параллельной нумерацией версий, мёртвый каталог `legacy/`, «бог-объект» `ESFService`.

**Оценка по направлениям (0–10):**

|---|:---:|---|

## 2. Стратегический риск №1 — клон госформы (S-0)

Это **не баг кода**, а фундаментальный риск продукта, и он важнее всех технических находок вместе взятых.

**Факты (из кода и docs):**
- Документ — «пиксель-точный клон «Копия 6.pdf»» с точным шрифтом DejaVu Sans и «официальным форматом QR» (PROJECT_STATE, TD-005, TD-011).
- `PUBLIC_BASE_URL` **по умолчанию** = `https://esf.salyk.kg` (реальный портал ГНС КР) — и в `config.py`, и в `.env.production.example`.
- Публичная «страница верификации» и QR ведут на **государственный** домен, где выпущенные этим приложением документы **не существуют** → QR либо не проверится, либо создаст ложное впечатление проверки.
- Документация **сама признаёт**: «Out of scope … ЭЦП/digital signature, **legal validity**».

**Почему это критично:** система, которая (а) визуально неотличима от официального налогового документа, (б) по умолчанию ссылается на реальный госдомен, (в) не имеет юридической силы — создаёт прямой риск использования для введения в заблуждение/подделки, а также юридической ответственности владельца. Технически код чистый, но продукт в текущей подаче — юридически опасный.

**Рекомендации (обязательно до любой демонстрации вовне):**
1. Убрать госдомен из дефолта: `PUBLIC_BASE_URL` должен быть обязательным без значения по умолчанию — приложение должно fail-closed при пустом значении, как уже сделано для `SECRET_KEY`.
2. Ввести неустранимый визуальный маркер во **всех** режимах (edit/view/public/pdf): водяной знак «ДЕМО / НЕ ЯВЛЯЕТСЯ ОФИЦИАЛЬНЫМ ДОКУМЕНТОМ ГНС», управляемый флагом окружения.
3. Явно задокументировать назначение продукта (внутренний макет/тренажёр/шаблонизатор) в README и добавить дисклеймер на публичную страницу.
4. Юридическое ревью назначения перед любым внешним использованием.

## 3. Детализация по направлениям

### 3.1 Архитектура и код

**Сделано хорошо (подтверждено):** слои в целом соблюдены, весь raw-SQL заперт в `repositories/`, роутеры без SQL; модели — нативные PG-enum, корректные FK (`ondelete=RESTRICT/CASCADE/SET NULL`), иммутабельность снапшота на ORM+DB; **ноль** TODO/FIXME/HACK в проде; dev-роуты (`dev_preview`, `dev_sample`) монтируются только при `ENVIRONMENT=development` (а дефолт — production).

**Недостатки:**
- **A-1 God-object.** `ESFService` (737 строк) совмещает запросы, пагинацию, dashboard-stats, create/duplicate/correction, batch, весь lifecycle, save/validate/publish, QR, пересборку позиций и два сериализатора. → Разбить на `ESFMapper/Serializer`, `ESFLifecycleService`, `ESFQueryService`.
- **A-2 Утечка слоя.** 10 мест в `esf_service.py` дёргают `self.db.flush/refresh/add/rollback` напрямую — правило «нет доступа к БД вне репозиториев» нарушено самим ядром. → Спрятать за методами репозитория.
- **A-3 Мёртвый код.** `backend/legacy/` (591 строка, старая SQLite/ReportLab-реализация) не импортируется ниоткуда; TD-001 сам предписывает удаление после спринтов 4R–8R (они завершены). → Удалить (история в git сохранит).
- **A-4 Логика в контроллере.** `esf_batch_pdf`/`esf_pdf` рендерят шаблон+PDF+ZIP прямо в роутере. → Вынести в `pdf/export` сервис.
- **A-5 Дубль.** `snapshot_service.latest_snapshot` — мёртвая копия с `db.query(...)`, дублирует `ESFDocumentRepository.latest_snapshot`. → Удалить.
- **A-6 Тихие except.** `batch_publish` (`except: failed += 1`) и `audit_service` (`except: rollback()`) глушат ошибки без лога — особенно опасно для аудита (требование charter). → Сузить и логировать с request-id.
- **A-7 Модель.** `owner_id` nullable в `counterparty`/`good`. → Backfill + `NOT NULL`.
- **Тесты:** 72 функции в **одном** монолите `test_regression.py` (1069 строк), только end-to-end через HTTP; нет unit-слоя для `validation_service`, sha256-хеширования снапшота, билдеров запросов. Покрытие широкое, но структурно хрупкое.

### 3.2 Безопасность

**Подтверждено образцовым (не по комментариям, а по коду):** отсутствие IDOR (все изменяющие маршруты через `get_for_user → require_owner_or_admin`), UUID вместо sequential id, DB-триггеры append-only для снапшотов/аудита (`e6f7a8b9c0d1`), sha256-верификация снапшота при каждом чтении (fail-closed), атомарная публикация (`FOR UPDATE` + sequence + UNIQUE→409), CSRF (`compare_digest`), Jinja-autoescape без единого `|safe`, bcrypt с обработкой 72 байт, security-заголовки + HSTS в проде, `/docs` off в проде.

**Недостатки:**
- **SEC-M1** — brute-force: per-process/in-memory/по-IP, без per-account lockout, сброс при рестарте; при `WEB_CONCURRENCY=2` — фактически 2 независимых счётчика. → Redis, ключ (IP+username), абсолютный счётчик по аккаунту. (TD-019, но это самый эксплуатируемый пробел.)
- **SEC-M2** — `GET /qr/{uuid}.png` без auth пишет PNG и делает `commit()` на произвольном (в т.ч. чужом черновом) документе; ещё и оракул существования. → Сделать идемпотентным/read-only на GET; ограничить PUBLISHED; предгенерация при публикации.
- **SEC-L1** тайминг-энумерация логина (нет bcrypt при отсутствии юзера) → сравнивать с фиктивным хешем.
- **SEC-L2** logout по GET (CSRF-выход), login POST без CSRF → logout POST+CSRF, pre-session токен.
- **SEC-L3** сессии без ревокации/idle-timeout, cookie живёт 14 дней даже после logout → короче max_age + idle-claim + серверная версия сессии.
- **SEC-L4** CSP `unsafe-inline` для скриптов → вынести inline-JS, nonce/hash.
- **SEC-L5** нет DB-иммутабельности **строки документа** (только app-guard) → триггер на PUBLISHED/CANCELLED `esf_documents` для паритета со снапшотами.
- **SEC-L6** латентный SSRF/локальное чтение в WeasyPrint `url_fetcher` (fallback на `default_url_fetcher`) — сейчас безопасно (в src только валидированный UUID), но deny-by-default надёжнее.
- **SEC-L7** health отдаёт версию без auth; нет `TrustedHostMiddleware`; дефолтные `esf:esf` в DATABASE_URL (dev-only).

### 3.3 Инфраструктура / окружение / CI

**Хорошо:** non-root `appuser` (uid 10001), прод-БД не проброшена на хост, dev-БД — только loopback, `.dockerignore` исключает `.env*`/`tests`/`legacy`/`.git`, entrypoint `set -e` и **не** создаёт админа автоматически, линейная неразрушающая история из 10 миграций, edge-rate-limit + `client_max_body_size 10m` + HTTP→HTTPS + HSTS в nginx, `pip-audit` в CI, fail-closed на пустой SECRET_KEY.

**Блокеры продакшена:** I-1 (самоподписанные `localhost`-сертификаты), I-2 (реальные секреты на синхронизируемом Desktop — ротировать), I-3 (образ не собирается в CI).
**Прочее:** I-4 (CSP unsafe-inline), I-5 (`forwarded-allow-ips='*'`), I-6 (нет lock-файла), CI-1 (нет порога покрытия), нет digest-пиннинга образов, нет `HEALTHCHECK` в Dockerfile, auto-migrate на каждом старте (гонка при масштабировании), нет resource-limits, health-проба на `/`, минимальный TLS-cipher-конфиг, бэкапы только в виде инструкции (не автоматизированы), пустой `docker/`, нет секрет-сканера в pre-commit, `ruff` только `F,I` (без bandit).
